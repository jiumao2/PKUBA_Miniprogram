# 领队报名

## 入口和资料

小程序“我的 → 球队报名与领队传承”办理创建、填写、提交、名单变更和交接；网站“球队报名审核”
设置报名截止时间、查看资料、指定组别及审核。管理员可给准备中赛季设置截止时间，先开放报名，
不必为了报名提前发布尚未完成的赛程。报名页可切换已开放报名的赛季；公开赛程仍只显示公开赛季。

每赛季一人一队、一队一名当前领队。创建报名即取得本队报名管理身份；审核通过后才关联正式
球队、球员和比赛工作台。既有球队的领队可关联本队报名资料，提交补充资料或名单变更，不能
借此再创建另一支正式球队。比赛相关权限仍以正式有效绑定和既有比赛规则为准。

球队必填名称和球服颜色；领队必填姓名、电话、邮箱；每个队员必填学院、姓名、学号、球衣号码。
人数不设上下限。学号按文本保留前导零；去除首尾空白后在同赛季判重。号码使用既有 0–99 或 00
格式，不能在同队重复。报名沿用既有正式名单的同队姓名检查，不把姓名作为跨队身份。

报名表、联系资料、学号、提交快照和审核意见只供本队当前领队及管理员查看，不写进公开账号、
公众接口、微信通知正文或通用审计正文。公开端仍保留队名和既有球员统计。私密资料按权限进入
赛季私有归档与系统备份，不进入公开导出或代码仓库。

## 期限、状态与占用

- 管理员设置带时区的截止时间；未设置时不开放。截止瞬间按服务器时间判断。
- 草稿不占用学号。提交时校验必填资料，并在同一事务占用队员资格；数据库唯一约束防止并发重复报名。
- 待审核版本不能直接覆盖。管理员指定本赛季唯一组别后通过；退回必须填写原因。
- 新报名被退回后释放学号。重提重新判重，不抢回已经被其他球队占用的学号。
- 截止后不能补交、编辑草稿、重提或发起增删申请。管理员可以继续审核截止前提交的版本；截止后被退回仍不能重提。
- 审核通过后正式名单锁定。截止前增删需填写原因并提交审批，审批前正式名单保持原状。
- 名单变更审核期间保留原正式成员资格，并预占拟新增成员；退回释放拟新增资格，保留正式名单。
  批准后释放移除人员资格。既有球员稳定 ID 不变，移除后本队重新接纳同一学号时复用原身份。
- 其他管理员维护正式名单后，旧变更申请不能直接批准覆盖；应退回并重新核对。

提交和审核分别留存不可变版本，不原地覆盖旧提交。可变申请带版本号；过期版本返回 409，
失败事务不留半支球队、部分名单或部分学号占用。关键命令支持原幂等键核对；重放只保存稳定 ID，
返回资料前重新检查当前权限，旧领队不能通过重放取回交接后的报名资料。

## 领队传承

原领队输入接任者已注册的唯一昵称并发起；接任者在报名页看到待处理交接，填写自己的联系资料，
接受后直接生效。双方都可拒绝或取消待处理交接。接任者必须启用且在该赛季没有其他球队。
新发起的交接会取消此前尚未接受的交接；申请版本或原领队身份变化后，旧交接不能继续生效，
须重新发起。接受、身份转移、历史绑定释放、审计与通知原子保存。

交接不受报名截止时间限制，但归档赛季只读。旧领队交接后立即失去资料访问权，历史提交人与
旧绑定作为证据保留。管理员纠正正式领队仍沿用现有超级管理员预览、确认和审计流程；纠正后
报名权限随正式绑定更新。不得通过直接修改数据库字段绕过该流程。

## 迁移与运行边界

新增模型、学号预约、历史身份及数据库触发器采用增量迁移；不会回填真实学号或猜测旧名单身份。
既有球队尚未补全学号时，只能对已填并提交的资料执行学号判重，管理员须核对未关联的旧名单。
准备中赛季首次整季名单导入不得覆盖已有报名；新报名通过后不再依赖整季导入。

有待审核报名或待接受交接时不能归档。归档后新功能普通入口只读。
实施新报名后不能仅因为旧应用可读取原表就认定旧版本可回切；开启截止时间前须确认所有写入
实例支持报名、身份与通知合同，按项目部署流程选择兼容应用，不通过删除申请或回退迁移清空新数据。

数据库字段、接口、生成客户端、两端页面及测试须一起发布。上线前在隔离 PostgreSQL、浏览器、
微信开发者工具及真机验证期限、并发、交接和隐私，不将组件测试当作真机验收。
