# 已知问题与处置登记

本文是后续维护者和 Agent 在处理安全扫描、依赖升级、清理建议和“行为改进”前必须核对的
公开处置登记。它只保存可以公开的摘要和用户决定，不替代缺陷跟踪、动态测试、机器门禁或
私密安全报告。

最新用户决定仍具有最高优先级。登记项没有命中重新打开条件时，不得因为扫描器仍显示告警、
工具建议升级或实现者认为可以“顺手改进”，擅自推翻既有处置。

## 处置值

| 处置 | 含义 |
| --- | --- |
| `FIX_REQUIRED` | 已确认需要修复；仍须遵守登记边界和当前任务授权。 |
| `KEEP_AS_DESIGNED` | 当前行为符合产品设计；未经用户重新确认不得改变。 |
| `FALSE_POSITIVE` | 报告不适用于登记边界；不得为了清零告警制造无关改动。 |
| `ACCEPTED_RISK` | 风险真实存在，但用户在登记边界内接受；不等于已经修复。 |
| `DEFERRED` | 已知问题延期到复核日或触发条件；不等于忽略或已经修复。 |
| `REVIEW_REQUIRED` | 新证据或边界变化需要用户复核；在决定前保持现状并停止扩张性修改。 |

技术测试状态与产品处置必须分开记录。测试 `PASS` 只证明已验证的合同成立；
`ACCEPTED_RISK`、`DEFERRED` 或开放告警也不能被写成 `FIXED`。

## 使用规则

1. 开始安全清理、依赖升级、告警处置或行为“优化”前，先按稳定 ID 搜索本文件。
2. 命中有效的 `KEEP_AS_DESIGNED`、`FALSE_POSITIVE`、`ACCEPTED_RISK` 或 `DEFERRED`
   时，候选不得修改对应行为、升级绕过、关闭或驳回外部告警，也不得宣称问题已修复。
3. 未命中的新告警或新问题默认标为 `REVIEW_REQUIRED`。发现本身只授权诊断和报告，不授权
   修改代码、配置、依赖、数据或外部告警状态；必须先向用户逐项报告问题、严重度、证据和
   修复选项，并取得对是否修复及修复方式的明确确认，才能转为 `FIX_REQUIRED` 并实施。
4. 只有登记的重新打开条件被真实证据触发时，才把状态报告为 `REVIEW_REQUIRED`，列出证据
   并请求用户决定；不得自动转为 `FIX_REQUIRED`。
5. 公开登记不得包含利用步骤、AppSecret、令牌、OpenID、真实账号、私密 URL 或其他尚未
   公开的敏感细节。敏感证据应保留在 GitHub 私密 Security Advisory；无法访问私密记录时，
   停止猜测并询问用户。
6. 候选交接必须列出命中的处置 ID、适用边界和是否触发重新打开条件。关闭、驳回或修改
   GitHub 安全告警是独立外部变更，需要用户对精确告警另行授权。

## 登记模板

新增登记项时至少填写以下字段；没有复核日期时写“无固定日期”，不能留空。

| 字段 | 要求 |
| --- | --- |
| 稳定 ID | 不复用、不改义的短标识。 |
| 来源 / 公开引用 | 可公开的扫描器、文档、代码或规范路径。 |
| 公开安全摘要 | 只写判断所需的最少信息，不写利用细节。 |
| 技术状态 | 已验证、未验证或阻塞，以及它不能证明什么。 |
| 产品处置 | 上述六种处置之一。 |
| 适用边界 | 精确说明该决定覆盖和不覆盖什么。 |
| 用户决定日期 | `YYYY-MM-DD`。 |
| 复核 / 到期日 | 固定日期或“无固定日期”。 |
| 重新打开条件 | 能够触发重新报告的客观变化。 |
| 禁止动作 | 后续 Agent 未经重新确认不得执行的动作。 |
| 私密记录引用 | 仅写“存在（仅授权者访问）”或“不适用”，不写私密 URL。 |
