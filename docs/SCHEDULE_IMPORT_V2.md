# PKUBA 赛季初 XLSX 赛程导入 V2

本文件是管理端赛程导入、后端校验和静态模板的共同约定。静态基线为 `docs/templates/PKUBA_赛程模板_v2.xlsx`；实际使用时优先在管理端选择准备中的赛季并下载动态模板。

## 1. 前置数据与写入边界

导入前数据库必须已有 `Season`、`Division`、`Team`、`Period`、`PeriodCapacity` 和 `Venue`。XLSX 只允许创建：

- `CompetitionGroup`
- `ParticipantSlot`
- `Game`

导入不会创建或修改球队，不写 `DrawAssignment`，也不会更新或删除既有比赛。每个导入创建的对象都保存确认批次来源，供审计和安全重置使用。

## 2. 工作簿格式

格式版本为 `2.0.0`，工作簿必须且只能按顺序包含四个可见工作表。文件不需要由服务器签发，不含隐藏元数据、HMAC 或 `leader_adjustable`。

### 管理员最简填写路径

模板交互参考旧 `schedule_template.xlsx` 的“直接看对阵、直接排进网格”习惯：管理端动态模板预填组别、已有签位、日期、星期、时段和场地，容量等基础数据只在赛季设置中配置一次，不要求管理员在 XLSX 重复填写。管理员通常只需：

1. 在“比赛清单”补充本次比赛；
2. 在“赛程网格”通过下拉或粘贴把比赛编号放到一个场地格；
3. 上传后检查校验预览并确认。

比赛编号允许使用人可读文本，推荐写成 `男甲·A1vsA2` 或 `女乙·城环vs中文`；同一对阵重复时再追加日期或短序号。不要要求管理员处理数据库 UUID 或冗长的内部迁移 ID。

### 填写说明

包含格式版本、赛季说明、填写规则和错误处理方式。服务端读取 `B4` 的格式版本。

### 赛制定义

表头位于第 5 行，字段顺序固定：

| 字段 | 规则 |
|---|---|
| 组别代码 | 必须匹配当前赛季已有 `Division.code` |
| 小组代码 | 可留空；非空时与组别代码共同标识小组 |
| 小组名称 | 小组代码非空时必填 |
| 小组排序 | 小组代码非空时必填正整数 |
| 签位代码 | 在组别内唯一，必填 |
| 签位名称 | 必填 |
| 种子序号 | 可留空；填写时为正整数 |

已存在且定义完全一致的小组或签位视为引用；同代码但定义不同是错误，不能覆盖。

### 比赛清单

表头位于第 5 行，字段顺序固定：

| 字段 | 规则 |
|---|---|
| 比赛编号 | 在赛季内唯一；数据库已存在时整批阻止确认 |
| 组别代码 | 必须匹配已有组别 |
| 小组代码 | 可留空；填写时必须匹配赛制定义或已有小组 |
| 阶段 | 小组赛、循环赛、淘汰赛、半决赛、决赛、保级赛之一 |
| 轮次 | 正整数 |
| 主方签位代码 | 必须匹配当前组别内的签位 |
| 客方签位代码 | 必须匹配当前组别内的签位，且不能与主方相同 |

日期、时段、场地统一在赛程网格填写。新比赛确认时固定设为 `leader_adjustable=true`，之后由管理员在赛程编辑器逐场修改。

### 赛程网格

- 第 5 行从 E 列起填写场地代码，第 6 行显示日期、星期、时段代码、时段名称及场地名称。
- 第 7 行起每行对应一个日期和时段；E 列之后的场地格填写比赛编号。
- 每个比赛清单中的编号必须且只能出现一次。
- 日期必须在赛季范围内，时段与场地必须属于当前赛季且开放容量允许。

## 3. 上传、校验与确认

上传限制为 10 MB；解压后总大小、内部成员数量也有限制。服务端拒绝宏、外部链接和单元格公式，并保存文件 SHA-256 用于确认前的一致性复核。

上传只创建暂存批次和问题列表，不写正式赛程。预览明确区分错误和警告，并提供新增/引用小组、签位数量、新增比赛数量以及完整比赛安排。主要校验包括：

- 未知或重复代码、结构冲突、双方相同；
- 比赛清单与网格缺失、重复或多余；
- 日期越界、时段容量、场地占用；
- 同一签位在同一时段参加多场比赛；
- 数据库已有比赛编号；
- 上传后发生的赛季版本或排期并发变化。

确认只允许超级管理员操作。服务端重新读取暂存文件并完整校验，锁定赛季及相关排期资源，然后在单一 PostgreSQL 事务中创建对象、写入批次来源、增加赛季版本和审计；任一错误都会完整回滚。

## 4. 多次导入与安全重置

允许同一准备中赛季进行多次新增式导入。后续批次可以原样引用已存在的小组和签位，但不能使用已有比赛编号；新文件未列出的旧比赛保持不变。

误导入通过管理端危险操作区处理：先执行重置预检，再输入完整赛季名称、勾选确认并完成浏览器二次确认。只有超级管理员能在 `SETUP` 状态执行；下列任一情况都会阻止整个事务：

- 已存在抽签映射；
- 导入比赛已开始、有比分或完成状态；
- 存在调赛申请、活动预留或比赛媒体；
- 待删除对象不是来自已确认导入批次，或被非导入对象引用。

成功重置只删除导入创建的比赛、签位和小组，将相关批次标记为 `ROLLED_BACK`，增加赛季版本并写审计；赛季、组别、球队、时段、容量、场地及所有手工对象均保留。
