# PKUBA 在线赛程编排与 XLSX V3.3

V3.3 以“赛制只配置一次、网页或 Excel 都只排对阵”为目标，采用一天一行的赛程网格。管理端“赛程编排”是主入口；XLSX 是同一服务器草稿的导入、导出格式，不是另一套流程。

## 1. 管理员最短路径

1. 在“赛季与组别”保存球队和签位方案；这里不配置赛程网格列。
2. 进入“赛程编排”。可直接拖动待排比赛或键入 `A1vsA2`，也可下载空白模板填写后上传。时间、场地、列顺序和“仅决赛”均在网格表头直接编辑。
3. 点击“保存并核对”，逐项确认完整性、数量、容量、列头、资源冲突和新增边界，勾选确认后才创建正式比赛。

容量、特殊日期覆盖和实时占用台账只在赛季配置中维护，不要求在 XLSX 重复填写。抽签和球队落位是后续步骤，导入时只使用待定签位。

## 2. 数据库前置与写入边界

编排前数据库必须已有 `Season`、`Division`、`Team`、`Period`、`PeriodCapacity` 和 `ScheduleSlotFamily`。场地来自列头自由文本，不要求存在 `Venue`，也不会由赛程导入创建 `Venue`。确认只创建：

- `CompetitionGroup`：仅小组赛或循环赛签位族按字母创建；
- `ParticipantSlot`：每个签位定义创建一个待定签位；
- `Game`：每个非空网格单元格创建一场比赛。

编排不创建或修改球队，不写 `DrawAssignment`，不更新或删除既有比赛。每个导入对象保存确认批次来源，用于审计和安全重置。在线草稿可以逐场设置 `leader_adjustable`；XLSX 不携带这个属性，上传的新格默认允许领队调赛。

## 3. 上游赛制配置

`ScheduleSlotFamily` 字段为 `division`、`stage`、`prefix`、`slot_count`、`sort_order`。代码必须是一个大小写敏感英文字母加连续正整数，例如 `A1`、`A2` 或 `a1`；`A` 与 `a` 是不同前缀。同一性别内，一个前缀只能属于一个组别和阶段，男、女可以复用同一前缀。

- 小组赛/循环赛签位总数必须等于该组别启用球队数；
- 半决赛固定 4 个签位，决赛固定 2 个；
- 淘汰赛、保级赛等其他阶段不少于 2 个且为偶数。

每个赛季有一份版本化 `ScheduleGridDraft`，其动态列保存 `period`、自由文本 `venue_name`、`final_only` 和顺序；非空格保存日期、对阵和逐场 `leader_adjustable`。草稿与正式 `Game` 隔离，自动保存采用乐观锁并写审计。

新空白草稿提供以下 16 个便捷初始列。它们只是可以立刻增删、改名、换时段和排序的默认排版，不是系统标准，也不参与上传文件兼容判断：

| 时间 | 场地 |
|---|---|
| 12:50 | 五四东一、五四东二、五四东三 |
| 14:20 | 五四东一、五四东二、五四东三 |
| 15:50 | 五四东一、五四东二、五四东三 |
| 18:30 | 邱德拔，仅决赛 |
| 18:20 | 五四东一、五四东二 |
| 19:50 | 五四东一、五四东二 |
| 20:30 | 邱德拔，仅决赛 |
| 20:40 | 五四东一 |

不支持旧赛季工作簿或旧格式转换，也不会从历史比赛反推草稿列。缺少签位族时返回“赛季与组别”补充。赛季不再处于 `SETUP` 时仍可导出查看，但不能确认新增赛程。

确认创建前必须显式通过六项核对：无缺漏或重复、比赛数量正确、比赛容量正确、日期与列头可识别、场地与参赛方无冲突、新增边界与并发安全。数量不一致会生成 `GAME_COUNT_MISMATCH` 阻断问题；确认事务仍会锁定赛季并重新执行全部校验。

## 4. 三页工作簿协议

当前格式版本为 `3.3.0`，只接受当前格式。工作簿必须且只能按顺序包含三个可见工作表，不含签名、隐藏赛季身份、HMAC、宏、外部链接或单元格公式。服务器只把第三页作为排赛业务输入；宏、公式、外链等安全检查仍覆盖整个文件。

### `填写说明`

由服务器生成，展示格式版本、赛季名称、日期范围、球队数、签位族摘要和错误处理方式，只需阅读。

### `签位定义`

固定三列：`组别`、`场次信息`、`签位代码`。服务器将“赛季与组别”中的签位方案展开为每行一个待定球队，例如 `男甲 / 小组赛 / B3`。本页只用于提示管理员每个字母的含义，无需填写或修改；即使文字被清空或改写，上传时也不会用于重定义签位。

确认时始终以数据库 `ScheduleSlotFamily` 为唯一来源：小组赛/循环赛以字母创建小组，名称自动为 `A组` 或 `a组`，数字后缀写入 `ParticipantSlot.seed`；淘汰赛、半决赛、决赛和保级赛签位的 `group=null`。

### `赛程网格`

- A 列是日期，B 列是自动生成的周一至周日，第 7 行起每行是一整天；日期范围由赛季起止日期完整展开。
- C 列起为 1–64 个连续动态列。第 5 行时间必须精确匹配当前赛季已有 `Period.start_time`；第 6 行场地是任意非空文本。同一“时段+规范化场地”不得重复。
- 场地写成 `邱德拔（仅决赛）` 或半角括号等价形式时，服务器剥离标记并把该列识别为仅决赛；在线编辑器提供同名勾选项。
- 日期、星期、表头和所有可填写单元格均保留清晰的细实线横纵边框；普通网格使用极浅绿色底，决赛专用网格使用浅琥珀底，便于横向和纵向对齐。
- `填写说明` 的规则区和组别汇总区同样使用显式细实线边框与浅色分区，不依赖 Excel 默认网格线。
- 单元格直接填写 `A1vsA2`。解析兼容任意大小写 `VS` 和空格，预览统一为小写 `vs`、无空格。
- 女子比赛必须以 `（女）` 结尾；解析兼容 `(女)` 和 `（女）`。模板中的女子比赛使用红色文字，男子为深色。

单元格双方必须属于相同性别命名空间、同一组别、同一阶段和同一签位族；小组赛/循环赛双方还必须属于同一小组。格内顺序保存为主客顺序，但 `A1vsA2` 与 `A2vsA1` 视为重复对阵。`round_number` 固定为 1，比赛编号由服务器根据组别、阶段和双方签位确定性生成。

## 5. 阻断性完整性与排期校验

- 数据库中每个小组赛/循环赛签位族必须覆盖全部 `n×(n-1)/2` 场两两对阵；
- 淘汰赛、半决赛、决赛和保级赛的每个签位必须且只能出现一次；
- 缺失对阵、未使用签位、同一对阵反向重复、双方相同或阶段不一致均阻止确认；
- 日期越界、时段容量超限、场地占用、同一签位同时参赛、已有同语义比赛、活动预留和并发版本变化均阻止确认；
- 决赛专用列放入非决赛比赛会直接报错。

多批导入只能新增一个完整的阶段或签位族，不能确认残缺签位族。新文件未包含的既有比赛保持不变。

## 6. 暂存、确认与安全重置

上传限制为 10 MB，服务端还检查压缩后体积和成员数量。结构检查通过后，XLSX 整表替换服务器草稿；非空草稿必须先在页面确认。业务错误仍保留在草稿中供在线修改。SHA-256 仅用于文件一致性记录。

在线编辑器支持占满视口的专注模式和可收起检查器。按住鼠标左键拖过单元格可形成矩形区域，批量男女篮和“领队可调/不可调”命令只在区域内至少包含一场比赛时启用；比赛移动改用格内独立抓手，避免与框选冲突并继续坚持只移动、不覆盖。表格工具栏提供 50%–150% 的缩放按钮、滑杆、当前比例与重置，表格内 `Ctrl/Cmd + 滚轮` 也只缩放整张网格，不触发页面全局缩放；缩放后保持当前查看位置并且不改变选择或数据。编辑器同时保留直接输入、TSV 复制粘贴、单次撤回粘贴、100 步会话撤回/重做、动态列增删/排序和服务器自动保存。上传和在线编辑最终都必须生成核对批次，核对前不会写正式赛程。

确认只允许超级管理员操作。服务端重新读取暂存文件、锁定赛季和排期资源并完整复核，然后在单一 PostgreSQL 事务中创建对象、写来源批次、增加赛季版本和审计；任一失败完整回滚。

误导入先执行重置预检，再输入完整赛季名称并二次确认。只有 `SETUP` 赛季可以重置；抽签映射、已开始或有比分比赛、调赛申请、活动预留、比赛媒体、非导入引用或不可追溯对象都会阻止整个事务。成功时只删除导入创建的比赛、签位和小组，保留赛季、组别、球队、容量、特殊日期覆盖、签位族、在线草稿列及手工对象。

## 7. 2026 北大杯示例

模板必须从当前赛季的“赛程编排”页面实时下载，格式版本由服务端固定为 `3.3.0`。仓库示例仅用于自动回归，不能替代页面下载的当季模板。示例以 16 个便捷初始列展示 51 个日期行、97 个签位和 146 场比赛；这些列可以编辑，不是服务器固定标准。女子比赛带 `（女）`，四场决赛使用两天的 18:30/20:30 + 邱德拔仅决赛列。文件须通过实际服务端解析器 0 错误、0 警告后发布。
