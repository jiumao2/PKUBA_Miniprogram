# 裁判与记录台报名和选派

## 流程与边界

管理员在管理站“裁判与记录台 → 人员资格”中，使用已注册用户的唯一昵称开通本赛季资格。
资格绑定现有微信账号，不建立独立密码，不改变普通用户、领队或管理员角色；同一账号可以
同时拥有其他身份。资格按赛季隔离，开通资格不授予网站管理员权限。

人员从小程序“我的 → 进入执裁工作台”选择有空的日期和赛季已有固定时段。报名对象为
“日期 + 固定时段”，不是单场比赛，不另设任意起止时间。日期必须位于赛季起止日期内，
固定时段必须属于同一赛季。当前不额外设报名截止时间；未公开和归档赛季不开放小程序报名。

管理员从某场比赛同日期、同时段的有效报名人员中逐岗位选派。选派保存后直接生效，人员
无需二次接受；小程序展示安排，同时在任务箱保留变动通知。微信通道按
[`WECHAT_NOTIFICATIONS.md`](WECHAT_NOTIFICATIONS.md) 配置模板和主动订阅后发送。

| 岗位 | 非决赛 | 决赛 |

| 主裁判 | 显示 | 显示 |
| 第一副裁判 | 显示 | 显示 |
| 第二副裁判 | 显示 | 显示 |
| 记录员 | 显示 | 显示 |
| 计时员 | 显示 | 显示 |
| 助理记录员 | 不显示、不接受选派 | 显示 |

以比赛的 `FINAL` 阶段识别决赛，半决赛不属于决赛。每个岗位可以留空，因此不强制每场
安排固定人数。当前按一人一岗、每岗一人校验；同一日期和固定时段内，同一人员只能有
一场有效选派。资格目前统一开通，未引入岗位认证或本队回避规则；这些规则若调整，需要
同步变更本规范、服务端、两端和测试。

## 调整、撤回与历史

- 人员可以撤回尚未关联未赛选派的报名，并可重新报名。同一日期时段复用原报名记录与稳定 ID。
- 已有关联未赛选派时，撤回报名或停用人员资格会被拒绝，须先联系管理员撤回相关选派。
- 管理员保存新的岗位名单时，原选派保留为历史，新增当前选派。留空或清空岗位可撤回原安排。
- 比赛日期、固定时段或开始时间变化时，原选派自动作废并释放时段占用，管理员须重新选派，
  不自动把人员调到新时段。作废与比赛更新处于同一数据库事务，失败共同回滚。
- 决赛变为非决赛时不再适用的岗位自动作废；比赛作废时全部原选派作废。历史安排在个人
  工作台标明已撤销。已完成或弃权比赛保留记录，不接受新增选派。
- 归档赛季在管理站只读，普通流程不增删改记录。

## 权限与数据

小程序只返回当前用户自己的资格、报名和安排。当前本场执裁组成员可进一步查看本场完整
岗位及昵称；没有本场有效选派、被撤回或因改期作废的人员均无权查看该场执裁组。
网站管理接口只供当前有效管理员使用。公众比赛接口不增加人员名单。响应不提供 OpenID、
手机号、邮箱、密码或会话凭据。小程序不提供已选派人员退出选派的操作。

新增资格、报名和选派均写审计；数据库唯一约束阻止重复资格、重复报名、重复岗位及人员
时段冲突。复合外键约束阻止跨赛季引用和报名与选派的人员/日期/时段不一致。

比赛写入的数据库触发器负责统一作废失效安排，覆盖普通调赛、管理员纠错和批量更新；每次
自动作废追加审计，原记录不可恢复为有效安排。重新选派创建新记录。

报名、资格修改和选派使用当前版本与 `Idempotency-Key`。网络结果不明时，两端锁住原操作，
使用同一请求核对，不更换键重建业务。版本变化返回 `409`，需刷新重新核对。新增集合接口
使用统一分页，不返回无界人员或赛季列表。

赛季导出包含三类新记录；全系统备份由既有一致备份流程覆盖。迁移仅新增表与约束，不修改
旧业务字段；对既有应用的回切和生产发布仍须按 `WORKFLOW.md` 单独验收与授权。
